System Overview

UAV 4D Conflict Resolution Pipeline

The framework implements a dynamic, strategic deconfliction service for U-Space operations. It leverages asymmetric priority allocation (VIP vs. Plebeian) and a deterministic cascading resolution engine. The architecture strictly isolates mathematical bounds generation from temporal orchestration.

Core Modularity

  • Detection: R-Tree Broad-phase + SAT Narrow-phase (detection/)
  • Resolution Cascade: Orchestrator managing S1, S2, FB1, FB2 (resolution/)
  • Geometry: Bézier Convex Hull verifications & Trapezoid routing.
  • Kinematics: Continuous degree-5 polynomial evaluations (Jerk, Snap, Crackle bounds).

Safety Guarantees

The system provides absolute deterministic safety via three pillars:

  • Separating Axis Theorem (SAT): Assures geometric non-intersection.
  • Shadow R-Tree Validation: Prevents Temporal Domino Effects prior to commit.
  • WCET Anchoring: Guarantees sufficient computation time for safe maneuver execution.
Phase 1

4D Conflict Detection

Continuous Collision Detection (CCD) is achieved via a two-phase spatial-temporal filtering mechanism. Trajectories are discretized into temporally overlapping Oriented Bounding Boxes (OBBs).

Broad-Phase: 4D R-Tree

The OBBs are enveloped in Axis-Aligned Minimum Bounding Rectangles (MBRs) across 4 dimensions $(x,y,z,t)$. The 4D R-Tree executes spatial intersections in $\mathcal{O}(\log N)$ time, rapidly rejecting non-interfering trajectories.

Narrow-Phase: SAT (OBB vs OBB)

Candidates from the broad-phase undergo extreme precision checks using the Separating Axis Theorem. We project the boxes onto 15 candidate axes:

// 15 Axes to test for separation:
A = [A.forward, A.right, A.up]
B = [B.forward, B.right, B.up]
Cross = { a × b | a ∈ A, b ∈ B }

if (∃ axis ∈ 15_axes where projections disjoint)
    return False // NO COLLISION
Phase 2

Temporal Orchestration & Invariants

Prior to applying geometrical alterations, the ConflictResolver establishes temporal constraints to ensure causal safety. The VIP aircraft is shielded from mission disruptions, while the Plebeian adapts.

The Anchor Time (t_anchor)

Maneuvers cannot retroactively alter the past, nor can they assume instantaneous computation and transmission. The Worst-Case Execution Time (WCET) margin is enforced mathematically:

t_anchor = max(t_conflict, t_start) + Delta_WCET
  • t_conflict : Earliest point of geometric overlap.
  • t_start : UAV's scheduled departure time (Hard Floor).
  • Delta_WCET : Configurable margin (e.g., 3.0s).

The Semaphore (VIP Hold)

To prevent the VIP from migrating into the conflict volume during computation, it is placed in a HOLD state (velocity equals 0) beginning at t_anchor. Subsequent waypoints are logically postponed via a sentinel offset.

Shadow R-Tree Validation

A clone of the R-Tree (omitting the Plebeian) is instantiated. Evaluative candidates replace the Plebeian's path in the shadow index. Only verified conflict-free paths merge into the primary registry, guaranteeing atomic safety commits.

Resolution Cascade

Strategy 1: Kinematic Bounding (ConnectURM2)

The initial resolution strategy prioritizes minimal spatial disruption by adjusting only the longitudinal velocity of the Plebeian along its original rectilinear trajectory.

1. Kinematic Guard Clause

Velocity alteration (ConnectURM2) assumes linear traversal (m = p_next - p_i). If high-order derivatives (acceleration, jerk > epsilon) define the active segment, the route is curved. Strategy 1 immediately bails to prevent geometric corruption.

2. Geometric Direction Decision

A projection of the relative position vector onto the VIP's forward heading dictates the tactical intent:

  • Positive projection: Plebeian is ahead → ACCELERATE to clear the zone first.
  • Negative projection: Plebeian is behind → BRAKE to yield the zone.

3. ConnectURM2 & The Ripple Effect

Once a candidate uniform speed is established via the Step Search algorithm, ConnectURM2 applies the new velocity to the active segment and propagates the resultant temporal offset to all downstream waypoints. This ensures contiguous polynomial interpolation remains intact, avoiding anomalous maneuvers.

# Extract geometric displacement m = p_next - p_i t_segment = |m| / v # Apply Uniform Rectilinear Motion (URM) w_i.vel = m / t_segment w_i.acel = w_i.jerk = w_i.snap = w_i.crakle = [0,0,0] # Ripple Effect: Propagate temporal delta t_des = (t_i + t_segment) - t_next for k in range(i + 1, len(waypoints)): waypoints[k].t += t_des
Resolution Cascade

SAT Minimum Translation Vectors (MTVs)

When Kinematic Bounding fails (or is obstructed by curved segments), spatial displacement is required. The system re-executes the Narrow-Phase SAT test to extract geometric expulsion vectors.

Isolating Candidate Axes

Instead of halting at the first separating axis, the engine calculates the overlap magnitude across all 15 SAT axes. The axes are scaled by a safety factor (1.05x) forming the Minimum Translation Vectors (MTVs).

These vectors are partitioned based on their dominant component and sorted natively by magnitude to minimize overall trajectory perturbation:

  • Horizontal MTVs: (X,Y) dominance → Passed to Strategy 2.
  • Vertical MTVs: (Z) dominance → Passed to Fallback 1.
Resolution Cascade

Strategy 2: Horizontal Path Stretch

A spatial detour is synthesized in the horizontal plane utilizing a Trapezoidal Evasion Geometry. The core innovation lies in mathematically guaranteeing collision-free traversal via Bézier curve properties.

The Trapezoid Detour

The original path is segmented into four new waypoints. The flat top of the trapezoid is routed strictly within a Safe OBB (the conflicting OBB translated by the spatial MTV).

[anc] → [det1] ===== [det2] → [ret]

Heuristic Curve Generation

The Trapezoidal geometry generates an optimal layout of Control Points along the Safe Center trajectory. By removing rigid mathematical pre-validation constraints, the system computes the 5th-degree polynomial trace purely via kinematic principles, permitting higher crossing velocities and less disruptive maneuvers.

Iterative Validation via Shadow R-Tree

The system attempts to clear the conflict utilizing the initial MTV magnitude. If the actual polynomial curve generated incurs in any temporal overlaps due to sweeping, the engine automatically scales the MTV iteratively (1.25x, 1.5x, 2.0x) and immediately queries the high-speed Shadow R-Tree to confirm complete temporal and spatial clearance prior to committing the trajectory.

Terminal Phases

Fallbacks & Deadlock Abort

In environments of extreme density or geometric constraint where S1 and S2 fail to yield mathematically valid safe paths, the engine downgrades to higher-disruption mitigation schemes.

FB1 Vertical Displacement

Functionally analogous to Strategy 2, but applies the Trapezoidal Evasion geometry against the Z-dominant MTV list. Multirotors exploit this cleanly by altering altitude exclusively.

FB2 Time-Shift (Hovering)

Sovereign halt mechanism. The Plebeian anchors at velocity v=0 via an inserted HOV_S to HOV_E waypoint envelope. Wait duration iterates by 0.5s intervals (up to 60.0s max) pending Shadow R-Tree clearance.

DEADLOCK Mission Abort

If hovering exceeds the 60.0s tactical limit without R-Tree clearance, structural insolvability is declared. Returns success=False requiring manual U-Space operator intervention.
